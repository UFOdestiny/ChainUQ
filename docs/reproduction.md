# Reproduction

All commands run from the repository root after `cp .env.example .env` (see the README). Each stage skips
outputs that already exist, so interrupted runs can be restarted with the same command.

## Pipeline

| Stage | Module | Device | Output (under `$CHAINUQ_ARTIFACTS`) |
|---|---|---|---|
| 0. Splits and pools | `pipeline.prepare_data` | CPU | `$CHAINUQ_DATASETS/<dataset>/hf_dataset`, `pools/n<N>/` |
| 1. Generation | `pipeline.generate` | GPU (vLLM) | `gen/<backbone>/<dataset>/<split>.jsonl` |
| 2. Judge labels | `pipeline.judge` (+ `scripts/serve_model.sh`) | judge server | `judge/<judge>/<task>/...` |
| 3. Features | `pipeline.features` | GPU | `feat/<backbone>/<dataset>/<split>/` |
| 3b. Side inputs | `pipeline.cotuq`, `pipeline.nli_steps`, `generate --n_samples 10` | GPU | `cotuq/`, `judge/nli/`, `gen/.../<split>.samples.jsonl` |
| 4. Heads | `pipeline.train` | GPU | `ckpt/<method>/...`, `preds/<method>/...` |
| 4b. Training-free baselines | `pipeline.scores` | GPU | `preds/<method>/...` |
| 5. Main comparison | `pipeline.evaluate` | CPU | `results/<backbone>/eval[_test2].json`, `tables[_test2].md` |
| Analyses | `experiments.*` | CPU (GPU for `adapt`, `benchmark`) | `results/paper/...`, `results/costs.json` |
| Paper | `experiments.paper` | CPU | `$CHAINUQ_PAPER_DIR/table/*.tex`, `fig/*.pdf` |

`python -m chainuq.pipeline.audit --backbone <b>` checks parse failures, truncation, judge parse failures,
label balance, and feature integrity of one backbone.

## Driver scripts

| Script | What it runs |
|---|---|
| `scripts/run_main.sh` | judge server; per backbone `scripts/run_backbone.sh <b> gen|judge|heads`; `evaluate` on test and test2 |
| `scripts/run_verifiers.sh` | Qwen3-4B correctness labels (label robustness), Qwen3-1.7B and self step labels (verifier swap) |
| `scripts/run_ablations.sh` | head ablations, UHead + PCS, label efficiency, `experiments.analysis`, `experiments.significance` |
| `scripts/run_adaptation.sh` | unlabeled pools, `experiments.adapt` / `adapt_eval` with all controls, verifier strength, pool size |
| `scripts/run_paper.sh` | `experiments.costs`, `experiments.benchmark`, `experiments.paper` |
| `scripts/reproduce.sh` | all of the above in order |

The scripts use `CHAINUQ_GEN_GPU` for generation, features, and training and `CHAINUQ_JUDGE_GPU` for the vLLM
judge server. The full reproduction takes several GPU-days on two 80 GB GPUs; most of it is generation and
judging, while R-Log fits and evaluation run on CPU.

## Protocol

- Heads are trained on HotpotQA train only, early-stopped on HotpotQA validation, with 10 seeds (2026-2035);
  every table reports the mean (and std) over seeds.
- Every calibrator and threshold is fit on the validation split of the evaluated dataset and applied once to
  its test split. `test2` is a fresh held-out split (seed 2027), evaluated once with the frozen pipeline.
- The evaluation set of a cell is the set of parsed responses with a correctness label and a valid step
  judgment, so methods with and without a judge are scored on the same responses.

Generated by `python -m chainuq.experiments.paper` from the result files below (`table/dataset.tex`,
`model.tex`, and `search_space.tex` are written by hand).

| `table/test2.tex` | Test-2 replication | `<b>/eval_test2.json` | `pipeline.evaluate --split test2` |
| `table/calibration.tex`, `app_calibration.tex` | calibrators on the same head | `paper/<b>/<d>_test.json` (`calibrators`) | `experiments.analysis` |
